# P0.3 — Paper Position Sizing & Accounting

## Status

**Schema phase implemented. Application integration is intentionally pending.**

## What changed

`db/migrate_p0_paper_accounting.sql` adds explicit accounting fields to `paper_positions` and `paper_trades`:

- allocated capital
- risk per trade
- risk amount
- stop distance
- quantity
- notional value
- entry/exit fees
- funding P&L
- gross/net P&L on the closed-trade ledger

It also adds a generated key and unique index for OPEN positions so the database itself rejects duplicate active positions for the same symbol/market/timeframe/strategy.

## Position sizing contract

For a normal spot position:

`risk_amount = allocated_capital × risk_per_trade_pct / 100`

`stop_distance = abs(entry_price - stop_loss)`

`quantity = risk_amount / stop_distance`

`notional = quantity × entry_price`

For futures, the same risk model applies to price-risk sizing, while leverage/margin constraints must be applied separately. Leverage must never be used to increase the allowed risk amount silently.

## Important migration requirement

Run this migration only after the base paper tables exist. Existing OPEN rows must be reviewed before adding the unique OPEN-position constraint; if duplicate active rows already exist, they must be reconciled first.

## Remaining P0.3 work

1. Update `paper/engine.py` to calculate sizing through `backtest/accounting.py`.
2. Persist all sizing fields when opening a position.
3. Calculate unrealized dollar P&L from quantity, notional and current price.
4. Calculate realized dollar P&L on close.
5. Apply entry/exit fees consistently.
6. Accrue funding for futures positions.
7. Persist the canonical net P&L and R-multiple.
8. Handle unique-key conflicts as an idempotent duplicate-sync outcome rather than a user-facing server error.
9. Add integration tests using temporary/synthetic database fixtures.

## Do not mark P0 complete yet

This schema migration does **not** mean paper accounting is complete. The paper engine must consume these fields and use the canonical accounting functions before the P0.3 gate can be closed.
