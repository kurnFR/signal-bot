# P0.5 — Paper / Backtest Execution Parity

**Status:** Contract and regression tests added; engine integration remains the next implementation gate.

## Canonical lifecycle

Both systems must use the same semantic lifecycle:

1. Candle N closes.
2. Strategy evaluates only information available at that close.
3. A signal becomes a pending entry.
4. Entry executes at Candle N+1 open, subject to configured execution slippage.
5. Position becomes active.
6. Subsequent candles update unrealized P&L and evaluate exits.
7. Exit execution follows the documented bar/intrabar policy.
8. Canonical accounting calculates gross P&L, fees, funding, net P&L and R.

## Critical paper-trading rule

Paper trading must never use a future closed candle to retroactively establish a real-time entry. If the system polls only after Candle N+1 has closed, it cannot claim the exact N+1 open as a live paper fill unless that price was captured when the candle opened.

Therefore paper execution needs an explicit state machine:

`SIGNAL -> PENDING_ENTRY -> ACTIVE -> CLOSED`

A scheduler should process the pending entry at the first observation of the next candle, using the observed/captured open price. If that observation was missed, the system must use a documented missed-entry policy rather than silently backfilling the historical open.

## Exit policy

When OHLC data shows both SL and TP could have occurred in the same candle, the system must use one deterministic policy. The conservative default is to assume the adverse exit first unless lower-timeframe data is available.

## Accounting parity

Paper and backtest must call `backtest.accounting` for:
- position size;
- risk amount;
- slippage-adjusted execution prices;
- fees;
- funding;
- gross/net P&L;
- R-multiple.

No duplicate financial formulas should remain in `paper/engine.py`.
